# BSDM-Proxy v0.9.15

**Release date:** 2026-09-22  
**Type:** minor/feature release  
**Previous tag:** v0.9.14

## Highlights

- **Reverse-proxy OIDC finished, with Google and Apple** — multi-provider sign-in through `OIDC_PROVIDERS` and `OIDC_<ID>_*`, a `/-/login` picker, per-provider callbacks, endpoints from OpenID discovery, Apple ES256 `client_secret` from a `.p8` key, `nonce` + PKCE, session TTL and per-provider email-domain allowlists. Legacy single-provider `OIDC_*` variables keep working.
- **`id_token` signatures are now verified** — tokens are checked against the provider's JWKS (RS256/384/512, ES256/384) with key rotation, `alg=none` rejected, `azp` validated, unverified emails refused, an open-redirect guard on `return_to`, a cap on in-flight sign-ins and generic callback errors. Previously the payload was base64-decoded and trusted.
- **Hop-by-hop headers stripped on every outbound request** — `Proxy-Authorization`, `Connection`, `Keep-Alive`, `Proxy-Connection`, `TE`, `Trailer`, `Transfer-Encoding` and `Upgrade` no longer reach origins or cache peers. This closes a credential leak to origin servers and a CL.TE request-smuggling desync.
- **eBPF/XDP modernization behind an explicit arming gate** — dual-stack IPv4/IPv6 XDP filter, kernel drop accounting, a full `/api/ebpf/*` Control API and `bsdm_proxy_ebpf_*` metrics; the filter cannot be enabled from the control plane unless `EBPF_XDP_ENABLED=true` or `EBPF_XDP_ALLOW_RUNTIME_ENABLE=true` is set in the environment. `EBPF_XDP_ENABLED` now defaults to `false` in the shipped env file.
- **alert-worker ClickHouse latency control** — per-query deadlines, server-side `max_execution_time` / `max_result_rows` / `readonly=2` guards, slow-query logging, degraded-cycle abort with capped backoff, new metrics and four Prometheus alert rules.
- **Synchronous policy engine, `ProxyService` decomposed** — policy evaluation returns a structured result without awaiting, so CONNECT no longer parks on a future; access, cache and miss-completion paths live in their own modules with no behaviour change.
- **APEX Architecture Contract v1 gate** — the event and HTTP boundaries and ownership rules are declared in `apex-contract/manifest.json`, pinned to the canonical contract commit and enforced by a test in `bsdm-events`.
- **Dependency fixes** — `rustls` 0.23.45 (RUSTSEC-2026-0285), `wasmtime` 46.0.3 (RUSTSEC-2026-0268/0269), `nanoid` 3.3.19 (GHSA-2v37-7h3g-55p8, dev-only).
- **Docs** — measured per-module resource profile, Threat Intelligence (Shadow) Grafana dashboard, eBPF/XDP lab guide, retired phase labels and Scope Freeze banners on frozen modules.

## Upgrade

1. Pull or build the `v0.9.15` images or packages.
2. Preserve `/etc/bsdm-proxy`, `/certs`, and persistent data volumes.
3. If origin servers or cache peers relied on receiving the client's `Proxy-Authorization`, `Connection` or `Transfer-Encoding` headers, that no longer happens; nothing in a standard deployment depends on it.
4. If a deployment used the XDP filter, set `EBPF_XDP_ENABLED=true` explicitly: the shipped `bsdm-proxy.env` now leaves it off, and `PUT /api/ebpf/config {"enabled": true}` answers `403` until the environment arms it.
5. Reverse-proxy OIDC deployments: existing `OIDC_CLIENT_ID` / `OIDC_CLIENT_SECRET` / `OIDC_ISSUER_URL` / `OIDC_REDIRECT_URI` still configure a single generic provider. The issuer must now serve `/.well-known/openid-configuration` and a JWKS, since tokens are verified. See [authentication.md](../features/authentication.md) for Google and Apple.
6. Verify `/health`, `/ready`, `/metrics`, and `/admin/` on port `9090`.
7. Validate archive downloads with the adjacent `.sha256` file.

No intentional breaking control-plane API changes.
