# Release v0.9.3

**Тип:** patch release (v0.9.3)  
**Дата:** 2026-08-04  
**База:** `main` (after v0.9.2)

> Phase C agent control-plane path: telemetry batch, device enroll tokens, and
> optional mTLS CSR client certificates. Full notes:
> [CHANGELOG.md](../../CHANGELOG.md).

## Highlights (с v0.9.2)

### Agent events

- `POST /api/v1/agent/events` — local-policy decision batch
- Metrics `decision_source=local-agent`; optional Kafka / EVENT_SINK enqueue
- Lab `GET /api/v1/agent/events/recent`

### Enroll

- `POST /api/v1/agent/enroll` → one-time `device_token` (hash stored)
- Auth: `AGENT_ENROLL_TOKEN` or `CONTROL_API_TOKEN`
- Agent APIs accept device Bearer or control token
- Revoke clears token hash

### mTLS CSR (optional)

- Enroll body `csr_pem` → ClientAuth cert signed by proxy CA
- Identity bound to `device_id` / platform (CSR subject not trusted)
- Returns `client_cert_pem`, `ca_cert_pem`, fingerprint
- Spike: `cargo run -p agent-spike -- --enroll --mtls --once`

Guide: [pilot-agent.md](../getting-started/pilot-agent.md).

## Upgrade from 0.9.2

1. Keep production tokens; optional `AGENT_ENROLL_TOKEN` for enroll-only bootstrap.
2. Optional durable devices: `AGENT_DEVICES_PATH` (compose volume `agent-devices`).
3. CSR enroll needs proxy CA loaded (`./certs/ca.*` or in-memory CA when MITM off).
4. No intentional breaking API changes vs 0.9.2.

## Still reserved

- Control-plane TLS requiring client certificates
- CRL/OCSP, policy push, multi-OS installers
