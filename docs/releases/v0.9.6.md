# Release v0.9.6

**Тип:** patch release (v0.9.6)  
**Дата:** 2026-08-04  
**База:** `main` (after v0.9.5)

> Agent **CRL + lab OCSP**, **agent_api** module extract, and Admin Console
> **Devices** page. Full notes: [CHANGELOG.md](../../CHANGELOG.md).

## Highlights (с v0.9.5)

| Surface | Purpose |
|---|---|
| `GET /api/v1/agent/crl` | JSON CRL (fingerprint / serial / device) |
| `GET /api/v1/agent/crl.pem` | CA-signed X.509 CRL when CA allows CrlSign |
| `GET /api/v1/agent/ocsp/status?fingerprint=\|&serial=` | Lab JSON status (`good`/`revoked`/`unknown`) |
| `proxy/src/agent_api.rs` | Agent Contract HTTP handlers (`dispatch_agent`) |
| Admin Console `/devices` | Registry list/revoke, policy push, events, CRL |

Also: revoke adds certs to CRL; mTLS optional `CONTROL_MTLS_CHECK_CRL`; enroll
returns `ocsp_status_url` when a client cert was issued.

Guide: [pilot-agent.md](../getting-started/pilot-agent.md) ·
[agent-contract.md](../architecture/agent-contract.md).

## Upgrade from 0.9.5

No breaking API changes. Optional ops:

```bash
# Durable CRL (recommended with AGENT_DEVICES_PATH)
export AGENT_CRL_PATH=./data/agent-crl.json

# Operator UI: open Admin Console → Security → Agent Devices
# Policy push from console or:
curl -X POST -H "Authorization: Bearer $CONTROL_API_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"reason":"ops","actor":"ops"}' \
  http://127.0.0.1:9090/api/v1/agent/policy/push
```

Lab OCSP is **JSON status only** — not RFC 6960 DER wire format.
