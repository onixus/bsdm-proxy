# Release v0.9.2

**Тип:** patch release (v0.9.2)  
**Дата:** 2026-08-04  
**База:** `main` (after v0.9.1)

> Pilot day-2+ surfaces on top of 0.9.1: observability pack, Phase C agent lab
> path (policy pull + durable devices), one-model ML pilot docs. Full notes:
> [CHANGELOG.md](../../CHANGELOG.md).

## Highlights (с v0.9.1)

### Observability

- Admin Console Dashboard `decision_source` mix + Logs filter
- Pilot alert-worker rule subset ([pilot-alerts.md](../getting-started/pilot-alerts.md))

### Agent (Phase C lab / Beta)

- `agent-spike`: pull `/api/v1/agent/policy`, local SNI/pinning/mode evaluate, heartbeat
- Control plane: `sni_rules` / `sni_deny_patterns`, device list + revoke
- **`AGENT_DEVICES_PATH`** JSON persistence (compose volume `agent-devices`)
- Refactor: `DeviceRegistry` + modular spike ([pilot-agent.md](../getting-started/pilot-agent.md))

### ML (day-2+)

- One-model UEBA pilot path ([pilot-ml.md](../getting-started/pilot-ml.md),
  `scripts/run-ml-pilot-smoke.sh`) — not required for Hybrid day-1

## Upgrade from 0.9.1

1. Keep production tokens (`CONTROL_API_TOKEN`, etc.).
2. Optional agent inventory: set or accept compose default
   `AGENT_DEVICES_PATH=/var/lib/bsdm-proxy/agent-devices.json` (named volume).
3. Optional ML: `docker compose --profile ml up -d ml-worker` + smoke script.
4. No intentional breaking API changes vs 0.9.1.
