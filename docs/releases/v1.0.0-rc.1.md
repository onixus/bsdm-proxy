# BSDM-Proxy v1.0.0-rc.1

**Release date:** 2026-10-10  
**Type:** release candidate for v1.0.0 GA (pre-release)  
**Previous tag:** v0.9.15

## Highlights

- **Production readiness review closed.** An architecture review and an AppSec code audit of
  the GA components found 5 P0 and 17 P1 issues; all P0 and every P1 that blocks GA are fixed
  with regression tests. What remains is listed under *Known limitations* below.
- **GA scope defined.** Forward proxy / CONNECT / selective MITM, L1 cache, ACL and
  categorization, Basic auth, the control REST API and Admin Console, dns-sinkhole and the
  Kafka → cache-indexer → ClickHouse analytics path are GA. Everything else (Redis L2, LDAP /
  NTLM / Kerberos, alert/ml-worker, TI enforce, agent, AmneziaWG, eBPF, WASM, ICAP, DLP, OIDC
  IAP, cluster) is Beta / Lab / Frozen and is **off** in the production profile — see
  [project-status.md](../project-status.md).
- **Production profiles.** [`docker-compose.prod.yml`](../../deploy/compose/docker-compose.prod.yml)
  and [`values-production.yaml`](../../charts/bsdm/values-production.yaml): non-root, read-only
  rootfs, no capabilities, secrets from files / Kubernetes Secrets with fail-closed rendering,
  control plane not exposed.
- **Fail-closed production defaults in code.** In `DEPLOYMENT_PROFILE=production` the proxy
  refuses to start without a valid MITM CA, without a users file for Basic auth, or as an
  anonymous open proxy (unless `ALLOW_ANONYMOUS_PROXY=true`); lab APIs answer `404`; the
  fast cache path that skipped ACLs is ignored; loopback forwarding is blocked.
- **Security fixes.** Shared cache no longer leaks private responses or replays
  `Set-Cookie`; Host / target mismatch is rejected; SSRF checks resolved addresses for both
  GET and CONNECT; request bodies are bounded; `config/apply` can no longer execute commands
  or rewrite host-managed settings; agent device tokens are scoped to their own device;
  dns-sinkhole validates upstream answers and bounds its connections.
- **Supply chain.** Blocking CI gate on every PR (fmt, clippy, tests, feature builds,
  cargo-deny, Admin Console); all six images published per tag after a Trivy gate, with SBOM,
  provenance and cosign keyless signatures.

The full list is in [CHANGELOG.md](../../CHANGELOG.md) under `[1.0.0-rc.1]`.

## Upgrade

Read the [upgrade guide](../ops-and-dev/upgrade-guide.md) first — this release changes
behaviour and adds start-up checks. In short:

1. Back up `/etc/bsdm-proxy`, the CA directory and data volumes.
2. Set `MITM_CA_DIR` explicitly; `ca.key` must be `0400` / `0440` (or `0600`).
3. With `AUTH_ENABLED=true` and Basic auth, provide `BASIC_AUTH_USERS_FILE`; with
   `AUTH_ENABLED=false`, add a client-IP allow rule or set `ALLOW_ANONYMOUS_PROXY=true`.
4. Set `SEARCH_UPSTREAM_TOKEN` if the console searches through cache-indexer.
5. Enable lab APIs only explicitly (`AGENT_API_ENABLED`, `AWG_API_ENABLED`, `LAB_API_ENABLED`).
6. Verify the artifacts (`cosign verify`), then go through the
   [production readiness checklist](../ops-and-dev/production-readiness-checklist.md).

## Known limitations

See §7a of [production-deployment.md](../getting-started/production-deployment.md). The main ones:

- The MITM circuit breaker can still be tripped deliberately by three colluding clients
  (domain bypasses inspection for 15 minutes); alert `BsdmMitmBreakerTripped` covers it.
  Certificate-trust-only accounting and fail-closed for `malware` / `phishing` are planned for 1.1.
- `ALLOWED_CONNECT_PORTS` has no default — set it explicitly (e.g. `443`) in production.
- Console config apply audit goes to the log only; secrets containing quotes or `\` cannot
  be set from the console.
- On a cache MISS several `Set-Cookie` headers are merged into one (functional bug, 1.0.x).
- NTLM / Kerberos cache authentication by client IP (not GA); `kerberos_keytab` is AGPL-3.0
  and `sspi` pulls `rsa` (RUSTSEC-2023-0071) — both only in the non-GA auth features.

## Roadmap

[docs/roadmap.md](../roadmap.md): 1.1 — control-plane & trust hardening (breaker v2, RBAC
and audit log, TLS for the console, real SNI peek, event privacy); 1.2 — single-site HA and
GA for Redis L2, LDAP/Kerberos and TI enforcement; 2.0 — multi-site, multi-tenancy and a
separate signer so the control plane never holds the CA key.
