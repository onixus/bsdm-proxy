## Предложение №1 (основное): привести Threat Intelligence к fail-safe Shadow Mode

### Проблема

ADR-0008 (#323) и issue #330 фиксируют решение: **никакого enforcement из TI-фидов
до накопления shadow-метрик и оценки false positives**. Фактическое состояние кода
противоречит этому:

- `threat-intel` по умолчанию компилирует enforcement-артефакты:
  `TI_RPZ_ENABLED=true` (`threat-intel/src/config.rs:74`) генерирует `threats.rpz`
  для `dns-sinkhole` и `threat_domains.json` для Proxy ACL из «грязных» фидов
  (OpenPhish, PhishStats, Phishing.Database, URLhaus) без ручной модерации.
- SOAR API (`/api/v1/soar/block`) добавляет индикаторы прямо в хранилище, откуда
  они попадают в те же артефакты.
- Событий `threat_shadow_match` и пути оценки FP **нет вообще** (в коде
  `threat-intel` отсутствует понятие shadow), метрик совпадений по фидам нет.
- `docs/project-status.md` называет этот режим «Shadow / Collector», хотя от
  реальной блокировки пилот отделяет один шаг оператора — подключение
  сгенерированной зоны к `dns-sinkhole`, который в Day-1 является core-компонентом.

Риск: блокировка легитимного трафика в пилоте из-за ложного срабатывания фида —
ровно тот сценарий, который ADR-0008 запрещает.

### Предлагаемые изменения

1. **Fail-safe значения по умолчанию**: ввести `TI_ENFORCEMENT_MODE=shadow|enforce`
   (по умолчанию `shadow`). В shadow-режиме RPZ/ACL-артефакты либо не
   генерируются, либо пишутся с суффиксом `.shadow`, который `dns-sinkhole` и
   proxy не могут подключить случайно. `TI_RPZ_ENABLED=true` без явного
   `TI_ENFORCEMENT_MODE=enforce` должен давать shadow-поведение и warning в лог.
2. **Shadow-события**: при совпадении трафика с IOC прокси эмитит
   `threat_shadow_match` в Kafka (обычный конвейер → ClickHouse), запрос **не
   блокируется**. Поле — по образцу `decision_source`.
3. **Метрики**: `ti_shadow_matches_total{feed=...}` в Prometheus + страница
   ревью FP для SOC (достаточно Search-запроса в доке).
4. **SOAR block в shadow-режиме** возвращает `202` с пометкой `shadow` и создаёт
   индикатор только в shadow-выгрузке.
5. **Формулировки**: README и `project-status.md` — «Мониторинг угроз в режиме
   Shadow (Enforcement в разработке)», без «защиты» в настоящем времени
   (требование #323/#330 и текста ADR-0008).
6. **Написать сам ADR-0008** (`docs/adr/0008-*.md`) — файла нет, хотя ADR-0007 по
   аналогичной схеме уже оформлен и реализован.

### Критерии приёмки

- [x] Дефолтная конфигурация пилота не может заблокировать трафик по TI-фидам ни
      одним переключателем — нужно явное `enforce` (`TI_ENFORCEMENT_MODE`, `.shadow`-артефакты,
      Triple-Gate в `proxy/src/ti_enforce.rs`).
- [x] `threat_shadow_match` виден в аналитике; zero change в allow/deny path
      (`proxy/src/ti_shadow.rs`, колонка `threat_shadow_match` в ClickHouse).
- [x] Метрики совпадений по фидам доступны в Prometheus/Grafana
      (`bsdm_proxy_ti_shadow_matches_total{feed}`, алерты `prometheus/alerts/ti_shadow.yml`,
      дашборд `grafana/dashboards/bsdm-threat-intel-shadow.json`).
- [x] `docs/`, `project-status.md`, README синхронизированы (правило обновления
      из `project-status.md`) — ADR 0008, `project-status.md` «Мониторинг угроз (Shadow)».
